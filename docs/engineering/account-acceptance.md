# Disposable Portal account acceptance

These checks use the existing pinned Ghost 5/6 profiles and their official Portal bundles. Only the locally created `example.test` member is edited; all successful writes reach the stock loopback Ghost API. No real account, external mail or payment service is used.

| Flow | Evidence checked |
| --- | --- |
| Profile name save at 360px | Native Save returns HTTP 200, member API has the new fixture name and unchanged email, and a fresh page/profile shows the saved value. |
| Failed profile save at 1440px | Abort one loopback PUT; draft remains in the form, server state stays unchanged, Retry appears and no automatic retry occurs. Explicit Retry then persists through reload. |
| Cancel / return | Back and close discard the unsaved name, send no profile PUT and leave server state unchanged. |
| Newsletter preference | Native pointer control saves through Ghost, a fresh page reflects the value, and a second save restores the original subscription state. |
| Failed preference save | Abort one loopback PUT; the error appears and the selected draft remains, while the server remains unchanged. Reopening restores server state and subsequent real saves work. |
| Keyboard preference | Space activates the actual accessible control, the Ghost API persists the state and another activation restores it. Legacy switch state must also be exposed correctly. |
| Signout privacy | Anonymous home/membership/restricted HTML and the member endpoint expose no fixture name/email; Back navigation shows signed-out navigation and reopening the account route yields an empty signin form. No mail is sent. |

`account-results.json` stores statuses, fault type and attempt count, not member responses, cookies, tokens or entered values. Screenshots contain only the deliberate local fixture. `account-contrast.json` records computed foreground/background colors and unrounded WCAG ratios using the already tested calculation. Raw axe results remain in `accessibility.json`, including incomplete entries needing review.

Pointer cases wait for finite opening animations to settle, then click the visible switch's center in page coordinates. This also checks hit testing through the modern inert decorative markup to the surrounding native row; it does not bypass the UI by dispatching a member update or DOM click. Success still requires the real Ghost response and persisted value. `account-pointer.json` records the actual hit-test target/control role and request counts without form data.

The first account run, [40791734554](https://github.com/qq550723504/ghost-research-pro/actions/runs/40791734554), commit `8e13c55014bdf071b297271c1ec0359a2f566d34`, passed both profiles' save/retry/cancel/privacy and pointer-preference checks. It exposed missing legacy newsletter keyboard semantics, low-contrast account text/Back controls, a mismatched signout accessible name, nested modern switch controls and stale dialog-title references after changing forms. The adapter supplements only those semantics, focus and styles; it continues to invoke native Portal handlers and does not implement a member API or store profile drafts.

Portal 2.51's visual switch forwards keyboard activation to its existing click handler. Portal 2.72's row already handles keyboard/pointer actions, so its decorative switch and sole-child click-stopping wrapper are inert and the row remains the single accessible control. The graphic-center regression in workflow 40794540882 exposed that making only the inner switch inert left clicks on the outer wrapper, which stopped propagation and sent no PUT; keyboard activation still worked. The wrapper fix is checked by actual hit testing and persisted pointer writes. Profile and email-preference headings are included in the dialog-name lookup; fallback names clear stale references.

Manual contrast review of the fixed Ghost 6 capture in workflow 40792844634 found the Back control readable in theme blue `#174e8b` on white (8.403349889701094:1), account explanatory text in `#58657a` on white (5.903118508518366:1), and the visible help-arrow glyph in `#174e8b` on `#f9f9f9` (7.981634071862014:1). Actual computed ancestor backgrounds are solid, with opacity 1 and no filters or blending. The arrow is visible beside "Get help" in the screenshot; its raw axe contrast entry remains incomplete. These measurements and visual inspection resolve that default-palette glyph finding separately, using the conservative 4.5:1 text threshold, rather than changing axe's classification. The earlier stale ARIA reference is addressed by the explicit dialog-name assertion and heading fix.

The [controlled HTTP failure probes](account-http-acceptance.md) separately exercise 503/429 responses and record strict draft/session/feedback/recovery outcomes. Their results must be checked independently of the original aborted-request tests.

The [comment notification probes](comment-preference-acceptance.md) separately exercise real pointer/keyboard saves, reload/restoration and controlled aborted-request feedback with the disposable publication's native comment setting temporarily enabled. Their strict results are recorded independently in `comment-preferences.json`; adding the probes is not a passing result.

Scope limits: only name, newsletter subscriptions and the comment notification flag are written. Email-address changes/verification, custom fields, announcement preference writes, simultaneous edits, other HTTP failures and account deletion are not covered. Comment posting/moderation and actual notification delivery are not tested. Selected axe rules and keyboard tests do not establish full WCAG conformance or replace an actual screen-reader session; no full screen-reader acceptance was performed. Stripe lifecycle tests and project licensing remain separate release gates. Use the latest exact-head CI evidence for pass/fail results.
